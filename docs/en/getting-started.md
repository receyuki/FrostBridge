# Build, flash and pair

[English](getting-started.md) · [简体中文](../zh-CN/getting-started.md) · [Home](../../README.md)

## Requirements

- Tested board: **Waveshare ESP32-DEV-KIT-WROOM-32E-N4** (classic ESP32, ESP32-D0WD-V3 chip, 4 MB flash, no PSRAM). ESP32-C3/S3/S2 and other fridge layouts are unverified. Do not select a different board merely because its name includes ESP32.
- USB data cable and a stable USB power source. Disconnect other BLE clients from the fridge.
- A C15 or a fridge using the same protocol. Only the author's C15 has been physically verified; for another model, follow the [compatibility checks](compatibility.md).
- 2.4GHz personal Wi-Fi. Current USB provisioning accepts SSID 1–32 UTF-8 bytes and password 8–63 bytes; open/enterprise networks and 64-character hex PSKs are unsupported by this setup path.
- Python 3.10+ with venv/pip, Internet access for the first toolchain download, and several GB of free disk space. Local builds require no Node.js or AI service. On Windows install the board manufacturer's USB driver if needed; on Linux configure serial access/udev as described by [PlatformIO](https://docs.platformio.org/en/latest/core/installation/requirements.html).
- An iPhone/iPad and Apple Home for pairing. A home hub is needed for hub automations/away-from-home control; Web control works independently on the LAN.

Only the macOS Intel workflow has been physically verified by this project. Windows/Linux syntax below is a supported tooling design, not a claim that every driver/board combination has passed.

## 1. Install tools

Open a terminal in the extracted source folder:

```sh
python3 frostbridge.py setup
python3 frostbridge.py doctor
```

Windows: use `py -3 frostbridge.py setup`, etc. The wrapper creates `.venv` and uses `.platformio` for packages. Do not install the full developer snapshot lock for normal setup; `requirements.txt` is the minimal entry. VS Code's PlatformIO extension is optional.

## 2. Build the production firmware

```sh
python3 frostbridge.py build
```

The default `gateway` profile uses English factory accessory names. For Chinese, add `--homekit-language zh-CN` to build/flash to select `gateway_zh`. `gateway_en` remains an English compatibility alias. Web starts in English independently of browser language; use its language button to choose Chinese. Updates to an existing Chinese installation can explicitly keep the Chinese profile; no reset or re-pairing is needed.

On POSIX systems, `./scripts/pio run -e gateway` also uses the project's installed environment. The `frostbridge.py` wrapper handles both the interpreter and package directory on all supported hosts; no virtualenv activation is needed. `pio run` defaults to gateway, not a smoke sketch. Web assets are regenerated by the pre-build hook.

## 3. Flash over USB

Back up any existing application/data before using a board previously assigned to another project. This firmware uses the 4MB `huge_app` partition layout: one 3MB application, USB updates, no OTA or automatic rollback.

```sh
python3 frostbridge.py ports
python3 frostbridge.py flash --port PORT
```

Replace `PORT` with your actual device (`COM5`, `/dev/ttyUSB0`, or a macOS `/dev/cu.*` path). Do not copy an example port blindly. Close other monitors first. If automatic download mode fails, follow your board's BOOT/EN procedure and retry at a reliable USB connection.

Normal same-layout application updates preserve Wi-Fi, fridge binding, pairing and backup settings; the tool does not erase flash. That does not guarantee preservation when changing another project's partitions. Never use erase-flash as a routine update step.

## 4. Set Wi-Fi

```sh
python3 frostbridge.py wifi --port PORT
```

Enter the SSID and hidden password in the interactive terminal. They go directly over USB to the device; neither is saved to project files. If only the SSID is wrong, use `wifi --keep-password --port PORT` to retain the existing device-side password. Successful provisioning restarts ESP32.

Opening a serial port may also restart ESP32. Finish initial setup before starting full-day learning, and avoid opening monitors during a day you need to record continuously.

## 5. Select your fridge

Power the C15, keep it in range, and close its original app/nRF Connect.

```sh
python3 frostbridge.py bind --port PORT
```

The tool keeps one USB connection, scans, lists name/address/RSSI, asks for the index of **your** fridge, then waits for fresh state and the binding-save acknowledgement. Blank input cancels. Existing selections are kept. To intentionally change the target, use `bind --replace --port PORT`; do not reuse an index from a previous session.

Binding performs discovery and a known status query; it does not request a temperature, power or mode change. A different fridge advertising the same BLE service is not proof of protocol compatibility.

```sh
python3 frostbridge.py status
```

If mDNS does not resolve, use `status --host YOUR_LOCAL_IP` or find the device in your router. `status` uses read-only HTTP and does not open/reset USB.

## 6. Pair Apple Home

```sh
python3 frostbridge.py pair --port PORT
```

The command creates a self-contained private HTML/SVG QR page in `.local/pairing/` and opens it on this computer. No external QR website is used. Scan the computer screen from iPhone/iPad Home → + → Add Accessory. If needed, use manual entry/More Options and the displayed eight-digit code. For a terminal-only computer, `pair --no-open --port PORT` creates the file without opening a browser. This QR is for HomeKit pairing, not Wi-Fi setup; complete Wi-Fi first. Keep the setup code/URI/file private. If an uncertified-accessory prompt appears, continue only for your own device. Assign a room and names. macOS Home cannot add a new accessory; see [Apple's setup guidance](https://support.apple.com/en-us/104998).

No diagnostic pairing client or third-party Python HomeKit package is required for normal pairing. Existing paired homes are not removed by this command. Configure the Connectivity Probe/Probe Reply action as described in [Usage](usage.md).

## 7. Daily use and updates

Open **http://frostbridge.local** or its current LAN IP. Save it as a bookmark/home-screen shortcut. Use a USB charger once you no longer need flashing; the Mac is not the gateway. The fridge and ESP32 both need power.

For an update, close monitors and repeat the same-language `flash` command from the new source. Do not re-provision/re-bind/re-pair if existing configuration works. Daily backup defaults off on a new device; see [Usage](usage.md) before enabling it.
