# 冰箱兼容性

[English](../en/compatibility.md) · [安装](getting-started.md) · [首页](../../README.zh-CN.md)

FrostBridge 通过蓝牙发现设备，**不按商品型号名单限制连接**。不用把冰箱改名为 C15，也不用在源码中手填蓝牙地址。同品牌、同 App 或相同蓝牙服务只是接入线索，不能直接证明兼容。

| 设备／协议 | 当前状态 |
|---|---|
| 作者的 C15，单温区 | 电源、温控、ECO/MAX 已与面板／原厂 App 实机核对。 |
| 使用相同 Alpicool 类协议的其他单区冰箱 | 可按下列流程核验；本项目尚未实测。 |
| 双温区冰箱 | 当前只有单区状态与控制接口；**未实现第二温区独立控制**，不能视为双区完整支持。 |
| 不同 GATT 服务、帧格式或设置布局 | 需要研究并实现协议，不能靠填写型号解决。 |

## 尝试使用现有协议接入

1. 按[安装文档](getting-started.md)准备。记录冰箱准确型号、温区数量、原厂 App 及版本；在面板／App 中选择摄氏，随后断开／退出原厂 App 和 nRF Connect，释放蓝牙。
2. 运行 `python3 frostbridge.py bind --port PORT`，从本次扫描选择**自己的冰箱**。候选包括有名称或广播 `1234` 服务的设备，不代表每个候选都兼容。明确更换已有目标时才使用 `--replace`。若复用已配置的网关，先暂停原冰箱的家庭自动化与每日备用，避免它们打断新设备的核验。
3. 打开网页或运行 `python3 frostbridge.py status`，核对电源、ECO/MAX、单位、目标与当前温度。用面板／App 做一次明显的正常调整，释放手机蓝牙连接后再核对第二组。保存目标成功或温度看起来合理，都不能代替这两次核验。
4. 两组状态一致后，分别测试需要的控制功能。选一个在冰箱正常范围内、容易区分的温度，核对面板和新鲜回读；再结合正常使用验证 ECO/MAX 与电源。逐项记录结果，确认其他设置保持不变，不需要反复开关机。

电源／ECO 提示布局不支持，但温度读取或调温正常，这种组合是可能的。请分别报告，不把某一项成功当成所有功能都兼容。若显示不一致或无关设置发生变化，停止该项控制测试。没有额外“解锁命令”可以绕过未知布局。

## 源码目前支持到哪里

固定版本的 [BrassMonkey 参考库](https://github.com/klightspeed/BrassMonkeyFridgeMonitor/tree/11f185eff808d6aae79eba247f826a52ed093fc0)输入蓝牙地址，没有商品型号数据库；服务／命令／通知使用蓝牙基础 UUID 下的 `1234`／`1235`／`1236`。它可选的协议 `--bind` 与 FrostBridge 的本地选择设备命令含义不同。[上游 CLI](https://github.com/klightspeed/BrassMonkeyFridgeMonitor/blob/11f185eff808d6aae79eba247f826a52ed093fc0/fridge.py#L589-L668)

FrostBridge 检查帧头、长度与校验和，从 Query01 共同前缀解码**一个**温区。摄氏控制范围为设备回报区间与 −20…20°C 的交集。目标温度使用 `05` 命令，目前不再按协议 model 区分布局。电源／ECO 使用 Set02，已实现 24 字节状态帧，或 36 字节且负载 `D[28]` 为 `1` 的布局；从新鲜快照保留其他设置。其他 Set02 字段投影尚未实现。[解析／编码源码](../../src/protocol/AlpicoolProtocol.cpp)

协议中的 `model` 不等于冰箱铭牌上的型号。长报文不能单独证明双区，作者的单区 C15 也返回 36 字节。较新的[分型号源码](https://github.com/dandwhelan/Alpicool50l12vfridgefreezer/blob/3f7ec01eced922aae431bb90e9c92ac9a60bb0c2/index.html#L454-L465)可作为开发线索，不代表 FrostBridge 已支持那些布局。

## 什么时候需要开发者协助

请整理一份**脱敏兼容性报告**，包含：

- 准确型号、单／双温区、原厂 App 和版本、ESP32 板型、FrostBridge 源码版本，以及每项功能的成功／失败情况。
- GATT 服务／特征 UUID 和属性，完整查询响应及通知分片、时间。`status` 是解码后的快照，**不是原始协议抓包**。
- 两组面板／App 数值及对应解码／原始数据，说明改了哪个字段；保留布局不支持或其他错误码。

可用 `python3 frostbridge.py monitor --port PORT` 查看已有 USB 诊断（Ctrl+] 退出）。打开 USB 可能重启 ESP32。原始日志可能含地址和私人配对资料，应留在本地；分享前去掉蓝牙地址、配对码／URI、Wi-Fi 信息与其他设备，参见[安全说明](../../SECURITY.md)。查询失败时，nRF Connect 可提供 GATT 视图；发送其他数据前，应由开发者先明确有依据的查询与捕获流程。

维护者可以在没有其他型号实物的情况下编写和测试解析／编码，但真实回读和面板行为仍需设备持有者核验。新布局需要可追溯样本、解析测试和保留原字段的编码；第二温区还涉及状态、Controller、Web 与 HomeKit。验证后按**型号和功能**登记支持情况，不能从一台成功推导整个品牌。
